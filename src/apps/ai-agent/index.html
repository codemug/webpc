    Local

    Your local workspace

    The model and conversation run in this browser. Load model downloads about 600 MB–1.4 GB from Hugging Face, plus the local runtime. Cached weights may be reused. A compatible WebGPU device and enough memory are required.

    Stop ends only this chat's work; the other chats keep running and the model stays loaded for them. Stop while a model is loading unloads the worker to cancel the download. Changing or reloading the model ends every chat's work and unloads the current worker to cancel downloads and computation immediately. Load again to continue; downloaded cache files are kept. Closing the app also ends its worker.

    Cloud model (your key)

    Optional, on top of the local models: use a cloud model with your own API key. The key stays in memory only. It is never stored, exported or logged, and the key and this choice are cleared on reload, when the app closes and when the model is switched.

    Your files

    Grant folders or files from the Files app so Buddy can list and read them, and create or update files with your confirmation. Grants are per session. They are cleared on reload and when the app closes, and never saved. With a cloud model, file contents Buddy reads are sent to that provider.

    No grants yet.

    A semantic search index over the granted text files can be built on demand. It is memory only — cleared with the grants and never saved. Building downloads a 23 MB embedding model from Hugging Face on first use; it then runs entirely on this device, and only that download leaves the device.

    Vision tools (on-device)

    ocr_image reads the text in an image and remove_background removes its background into a transparent PNG named <name>-nobg.png. Both run on this device in their own worker with local models, independent of the chat model: the first use downloads the model from Hugging Face (OCR about 262 MB once; the engine below for background removal), then everything stays on this device and the vision tools themselves send nothing. They work on the attached image or on images inside the file grants above; remove_background saves a granted source next to it after your confirmation and offers a download for an attached image.

    Chrome built-in AI (on-device)

    Uses your browser's built-in models: chat, translation, summarization and language detection run on this device. The only network traffic is Chrome downloading its own models; nothing is sent anywhere else. Needs desktop Chrome with at least 22 GB free space and a GPU with more than 4 GB of memory (or 16 GB of memory and 4 cores).

    Image input

    Qwen models can read images. With Image input on, you can attach a PNG, JPEG or WebP of up to 10 MB; it is decoded and downscaled (longest side 768 px) in your browser before it reaches the model. The vision encoder downloads only when image input is first used — about 62 MB for the 0.8B model and about 197 MB for the 2B model. LFM3 is text-only and cannot use Image input. Attached images are not saved: the conversation keeps a text marker (for example [image: chart.png, 768×512]), so images are gone after a reload.

    Web tools

    Wikipedia search sends the search terms to Wikipedia. Page reading sends a request to the named site, without cookies. JavaScript runs in a fresh isolated sandbox with network access blocked.

    Off by default. If direct reading fails, this sends the requested URL (including its query string) to Jina. Do not enable it for private or sensitive URLs. This choice lasts only until the app closes.

    Conversation and recovery

    Local saves can be removed by your browser. Export important chats. Every chat is stored on its own, so New chat and Open backup never overwrite an existing chat. Older voice-agent records are copied on the same origin, never deleted. A different website origin cannot read the old app’s storage: export there and open the backup here.
